# Lin 2.1 / 2.2 / 2.3 兼容核对

2026-10-18。完整私人预设与聊天没有放入仓库。

## 可确定的差异

2.1 和 2.2 的主提示、辅助提示、本轮任务、原 assistant 承接、完整 user 尾部及六条正则完全相同。2.2 将 reasoning_effort 从 auto 改为 max，输出上限仍为 16,384；六个写作条目变化。全局开关还切换了戏外交流、转述后扩写、字数模式和小剧场。

2.2 的全局固定提示实际比 2.1 更短：约 26,442 对 32,138 字符，不含世界书与聊天。因此“2.2 因为总提示更长而空回”不符合本次文件。尾部的最大思考要求两版都存在，不能当作 2.2 新增变化。

max 与固定总输出上限是优先验证的预算风险。Google 文档说明思考与正文可共享输出预算，推理耗尽上限可能导致截断或空正文；具体渠道字段映射仍需实际记录。没有日志不能确定某次空回原因。

## Lin 2.3

相对 2.2 只增加版本名、将思考参数恢复 auto、加强一个去套话条目。其他 79 个条目、六条正则、开关和排序不变。整个尾部及全部沙盒相关原文逐字一致。

原承接 identifier、名称、角色与内容不变，因此 1.0.0、1.1.0 及本版的识别路径仍可使用；本版两种模式均已离线核对。预设恢复 auto 后，插件可保持默认“沿用当前参数”。

## 没有归因为新版的问题

- 两版均设很大的本地上下文值；本地设置不代表渠道容量。
- 两版均开启网页搜索；渠道若不兼容需要另查，但不是两版新差异。
- 两版 n 均为 0；不能用相同值单独解释新空回。
- 六条正则相同，未发现直接删除完整当前正文的规则；仍不能代替实际前端检查。

## 旧插件功能

1.0.0 消息规划及全部设置入口仍在；1.1.0 历史、发送观察和响应诊断保留。设置与历史键不改，旧的显式模式和自定义文字保留。更严格的核对只影响成功徽标，不妨碍发送，也不删除旧记录。
