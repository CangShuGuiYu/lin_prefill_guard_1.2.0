# Lin 预填充助手 1.2.0

SillyTavern Chat Completion 扩展，适配 Lin 2.1 / 2.2 / 2.3。在请求发送前整理普通任务承接消息，并提供可查询的注入与接口诊断。运行时无第三方依赖，无需构建。

它不是模型原生 prefill，不能保证模型执行提示或消除所有空回。不会自动重试、额外调用模型或改写模型回复。

## 安装与更新

仓库地址：<https://github.com/061029wjy-rgb/lin-prefill-guard>

在酒馆「扩展 → 安装扩展」粘贴仓库地址。已安装时，在扩展管理里更新本扩展并刷新页面；面板应显示 `v1.2.0`。ZIP、单个 JS 的 raw 地址和预设 JSON 不能代替仓库地址。

也可把完整 `lin-prefill-guard` 文件夹放入运行酒馆的服务器用户扩展目录，例如 `SillyTavern/data/<用户目录>/extensions/lin-prefill-guard/`，确保文件夹内直接有 `manifest.json`。手机只是访问远程酒馆时，仅下载 ZIP 到手机不会完成安装。本项目不是酒馆助手直接导入的脚本 JSON。

Lin 2.3 预设需在酒馆的预设入口另行导入。仓库不包含用户的完整预设、世界书或聊天。

## 设置与原有功能

| 设置 / 功能 | 行为 |
| --- | --- |
| 启用扩展 | 关闭即停止后续请求注入 |
| 适用范围 | 默认仅识别且启用的 Lin 承接条目；保留全部 Chat Completion 预设选项 |
| 注入方式 | 新安装默认单条 user；保留 assistant + user 双消息模式 |
| 原承接开关 | 保持原承接条目启用；默认范围内尊重其关闭及生成类型限制 |
| 自定义文本 | 两段提示仍可编辑、恢复默认；升级保留自定义内容 |
| 思考预算 | 默认沿用当前参数；Lin 2.3 的 auto 可直接沿用 |
| 继续补全 | 默认沿用酒馆；可选增强，原生继续预填充仍避让 |
| 发送与接口取证 | 默认开启，可关闭；关闭后保留请求组装记录 |
| 注入历史 | 最近 50 条，可搜索、选择、复制、导出、清空、刷新后恢复 |
| 本地自检与预览 | 不调用模型；自检不冒充真实发送成功 |
| 特殊请求 | 后台、用户代写、原生 prefill、工具调用、JSON 结构化请求自动避让 |

升级沿用 `lin_prefill_guard_v1` 设置键和 `lin_prefill_guard_history_v2` 历史键。旧用户的 pair / user 模式不被强制切换。仅当执行提示逐字等于 1.0.0 出厂文本时，才更新为新版出厂文本；自定义文本不变。1.0.0 没有保存的旧请求历史不能恢复。

单条 user 模式将短承接与执行提示放在请求末尾。双消息模式则放入 assistant 承接和 user 执行两条。仅完整匹配独立原承接消息时才替换，不拆分合并消息、不删除其他规则、历史或世界书。不修改保存的预设或聊天。

## 1.2.0 修复

- 重生成被酒馆转成 normal 事件时仍记录正文；继续补全支持 append / appendFinal，滑动重生成不把更早消息错认成本次结果。
- 同一请求重复触发组装事件时，保留发送、响应和正文证据，不把流式回复移出检查范围。
- 多个相同待发送请求不猜测对应关系；双消息必须逐条角色、内容、顺序一致，不能用一条提示的两份副本冒充完整注入。
- 仅有 `[DONE]` 的未知响应不再被判作已识别空回；区分拒绝字段、取证不完整与无正文。
- 带 thought 标记的文本块不当作普通承接消息移除。
- 可选预算降档区分 Gemini 3.0 Pro（low）与 3.1 Pro（medium）；已识别的 Gemini 2.5、3 系列 Flash、4 Argon 文本型号用 medium，图像、TTS 和未知别名不猜测。
- 保留 1.0.0 注入、设置、避让功能，以及 1.1.0 持久历史、发送核对和接口诊断。

预算降档只在主动选择后调整本次高 / 最大思考请求，不改保存的预设。字段映射取决于酒馆后端和渠道，文字提示本身不能预留真实 token。

## 查询空回

入口：**扩展 → Lin 预填充助手 → 注入历史**。

记录区分组装文本、发送边界核对文本、接口统计和酒馆保存的正文。有正文但屏幕为空时继续检查显示正则与样式；只有思考时结合结束原因和用量判断；有 HTTP 错误或拒绝字段时查看酒馆原错误。

“已组装”不表示已发送，“已核对发送”不表示模型必定执行。发送核对只覆盖同源 `/api/backends/chat-completions/generate` 的 POST 字符串请求体；其他接口、Request 对象形式或绕过 fetch 的脚本可能没有发送层记录。后端、中转及更内层拦截器仍可能转换数据。

响应仅读取副本，最多 2 MiB / 180 秒，超限会明确标记。不保存正文、完整聊天、密钥、请求头或思考原文，只保存插件提示和有限元数据。自定义提示也会写入诊断，分享导出记录前请检查。未知响应格式标为未识别，不假定为空。1.1.0 历史发送详情仍可查询，新版严格核对徽标只用于新核对结果。

注入位于主要预算分配之后，自定义长提示或原条目缺失时仍可能增加请求长度。本扩展不会删聊天腾出空间，也不扩大服务商窗口。

## 开发和验证

Node.js 20 或更新版本：`npm run check`、`npm test`。

本版完成 81 项自动化测试及 Lin 2.1 / 2.2 / 2.3 × 两种注入模式 × 三种生成类型的 18 次真实预设离线回放。未连接用户模型渠道，没有声称实测空回率或前端实机验收通过。

`core.js` 规划请求；`controller.js` 处理事件；`diagnostics.js` 保存历史和诊断；`observer.js` 只读观察响应；`index.js` / `style.css` 提供面板；`test/` 保存回归测试。

依据：[SillyTavern 请求流程](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/openai.js)、[回复保存与流式事件](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js)、[Gemini 思考与预算](https://ai.google.dev/gemini-api/docs/thinking)。核对日期：2026-10-18。
